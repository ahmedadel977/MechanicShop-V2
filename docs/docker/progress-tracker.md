# خطة التعلّم والتمارين

## متتبع الإنجاز

- [ ] أفهم الفرق بين الصورة والحاوية والـvolume.
- [ ] أتحقق من Docker Engine باستخدام `docker info`.
- [ ] أشرح سبب استخدام جذر الحل كسياق بناء.
- [ ] أشرح مراحل `build` و`final` في Dockerfile.
- [ ] أضبط `.env` دون رفعه إلى Git.
- [ ] أشغّل Compose وأقرأ حالات الصحة.
- [ ] أشرح DNS الداخلي ولماذا لا أستخدم localhost بين الحاويات.
- [ ] أتحقق من حفظ بيانات SQL في named volume.
- [ ] أتعقب log وtrace وmetric إلى الوجهة المناسبة.
- [ ] أوقف البيئة مع الحفاظ على البيانات.
- [ ] أميز إعداد تطوير محلي عن نشر Production.

## تمارين عملية

1. **افحص البيئة:** شغّل `docker version` و`docker info`. ما الفرق بين معلومات العميل والخادم؟ إذا تعذر الاتصال، أصلح Docker Desktop قبل المتابعة.
2. **تحقق من Compose:** شغّل `docker compose config --quiet`. غيّر اسم متغير مؤقتًا في ملف محلي ثم لاحظ رسالة التحقق، وبعدها أعده.
3. **تعارض منافذ:** غيّر `API_HTTP_PORT` إلى منفذ آخر، أعد إنشاء API، وتحقق من عنوان الصحة.
4. **DNS الداخلي:** من API تحقق من connection strings. لماذا عنوان SQL هو `sqlserver` بدل `localhost`؟
5. **حالة الخدمة:** أوقف Redis مؤقتًا ثم راقب صحة API. أعد تشغيله وتابع عودة الصحة.
6. **البيانات الدائمة:** أنشئ بيانات اختبار، أوقف Compose باستخدام `down` ثم ابدأ مجددًا وتحقق من وجودها.
7. **السجلات:** نفّذ طلب HTTP وتحقق من ظهور log في Seq. لا تضع بيانات حقيقية في الطلب التجريبي.
8. **المقاييس:** افتح Prometheus Targets وحدد سبب حالة DOWN إن ظهرت. افحص إعداد Collector قبل تغيير التطبيق.
9. **الحذف الآمن:** اعرض `docker volume ls` وحدد volumes الخاصة بالمشروع. لا تنفذ `down --volumes` على قاعدة مهمة.
10. **تطوير مقابل إنتاج:** دوّن التغييرات المطلوبة قبل نشر حقيقي: الترخيص، الأسرار، TLS، ترحيل قاعدة البيانات، النسخ الاحتياطية، والمراقبة.
